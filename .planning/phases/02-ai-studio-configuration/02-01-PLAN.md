**PART 2 — SYSTEM INSTRUCTIONS**

This is the text user will paste into AI Studio. Frame as:

```
You are a React developer building DesignDNA — an AI-powered design analysis app for Print on Demand (POD) sellers. You generate production-ready React code following these specifications exactly.

## App Overview
[2-3 sentences: what DesignDNA does, core value prop — Visual DNA + Buyer DNA]

## Design System
[EMBED the entire STYLE-GUIDE.md content here — all 9 sections inline]

## App Architecture & Conventions
- Single-page React app, client-side only
- No external npm packages — all code self-contained
- State management: React useState/useReducer (no Redux/Zustand)
- Routing: Simple conditional rendering based on state (no react-router)
- API calls: Use Gemini API via the built-in AI Studio integration
- Image upload: FileReader API → base64
- Error handling: try/catch with user-friendly error messages, no raw errors
- Loading states: Always show skeleton/spinner during async operations

## Analysis Modes
- **Quick Scan:** Visual DNA only, uses gemini-2.5-flash, same detail level as Deep
- **Deep Analysis:** Visual DNA + Buyer DNA, uses gemini-2.5-pro, more comprehensive
- Mode selection happens AFTER image upload
- Both modes use the same Visual DNA schema; Deep adds Buyer DNA schema

## Output Language
- All analysis output (DNA Card content) in English
- UI chrome (buttons, labels, navigation) in English

## Content Tone for Buyer DNA
- No confidence percentages — present findings directly
- Ambiguous designs: commit to 1 primary buyer profile + brief "Could also appeal to..." note
- "Made For Me" decisions: title is analytical/neutral, explanation is conversational/insightful
  Example: "Earth-tone color palette" → "Colors literally match the environment they love. Wearing these colors = wearing nature. Would FAIL in neon or pastels."

## Structured Output Schemas
When generating analysis results, output MUST conform to these JSON schemas exactly.

[INSERT JSON SCHEMAS FROM TASK ACTION BELOW]
```

**JSON Schemas to include inside System Instructions:**

**Schema 1: Visual DNA**
Based on APP-CONCEPT-V2.md Section 4, with these rules:
- `composition`: object with `grid_type`, `symmetry`, `focal_point`, `visual_flow`, `density` — all free-text strings
- `color`: object with `palette` (array of exactly 5 objects: `{hex, name, role}`), `harmony`, `contrast`, `temperature` — free-text strings
- `typography`: object with `fonts` (array of 1-3 objects: `{classification, weight, case, role}`), `hierarchy_levels` (number), `suggested_google_fonts` (array of strings)
- `graphics`: object with `style`, `primary_element`, `secondary_elements` (array), `effects` (array), `detail_level` — free-text strings
- `pod_technical`: object with `best_print_method`, `suitable_products` (array), `recommended_garment_colors` (array), `scalability` — free-text strings

**Schema 2: Buyer DNA**
Based on APP-CONCEPT-V2.md Section 2, with these rules:
- `persona`: object with `age_range` (string like "25-35"), `gender_lean`, `interests` (array), `values` (array), `lifestyle` (string, 1-2 sentences), `spending_mindset` (string), `online_communities` (array)
- `identity_signals`: object with `primary` (string), `message_to_world` (string), `tribe` (string), `aesthetic_identity` (string)
- `emotional_triggers`: object with `primary_emotion` (string), `trigger_description` (string, 2-3 sentences), `secondary_emotions` (array), `emotional_arc` (string)
- `occasion_timing`: object with `best_seasons` (array), `events` (array), `mood_triggers` (string), `gift_potential` (object: `{score, who_buys_for_whom}`), `evergreen_vs_viral` (string), `wear_context` (string)
- `made_for_me_decisions`: array of exactly 3-5 objects: `{decision, why_it_works}` — decision = neutral title, why_it_works = conversational explanation

**Schema 3: Complete DNA Card Output**
Wrapper combining Visual DNA + optional Buyer DNA:
```json
{
  "design_dna": {
    "visual_dna": { ... },
    "buyer_dna": { ... } // null for Quick Scan
  }
}
```

**Schema 4: Batch Compare Output**
Based on APP-CONCEPT-V2.md Section 6 (F3):
- `visual_patterns`: object summarizing cross-design visual commonalities
- `buyer_overlap`: object with `shared_buyer_profile` (persona, identity, emotion, occasion), `made_for_me_patterns` (array of strings), `buyer_insight` (string), `specificity_ladder` (object: generic/niche/hyper-niche)
- `winning_formula`: object with `visual` (string summary), `buyer` (string summary), `suggested_brief` (string — actionable prompt for generation)

**Schema 5: Generation Request** (SHIFT+B → Image Gen)
Structure for when user wants to generate a new design:
- `mode`: "same_buyer" | "new_buyer" | "full_remix"
- `creativity_level`: 1-5
- `shift_b`: object with 6 dimensions, each: `{action: "keep" | "change", value: string}`
- `specificity_level`: "general" | "niche" | "hyper_niche"
- `source_dna`: reference to original analysis

**PART 3 — MODEL SELECTION MAPPING**

Table format:
| Operation | Model | Rationale |
|-----------|-------|-----------|
| Code generation (Build Mode) | Gemini 3.1 Pro Preview | Best code gen quality |
| Quick Scan analysis | gemini-2.5-flash | Fast, cost-effective for visual-only |
| Deep Analysis | gemini-2.5-pro | Strong reasoning for buyer psychology |
| Image generation | gemini-3.1-flash-image-preview | Best speed/quality for POD designs |

**PART 4 — REFERENCE: ANALYSIS PROMPT TEMPLATES**

Include template prompts that the app will use internally when calling Gemini for analysis:
- Quick Scan prompt template (image + "Analyze Visual DNA")
- Deep Analysis prompt template (image + "Analyze Visual DNA + Buyer DNA")
- Batch Compare prompt template (2-5 images + "Compare designs")
- Generation prompt template (DNA + SHIFT+B settings → "Generate new design")

These are NOT System Instructions — they're reference templates for Phase 3-5 to use when building the app's API call logic.
