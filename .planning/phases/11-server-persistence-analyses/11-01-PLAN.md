# Plan 11-01: Backend Analyses CRUD Routes

## Objective
Create backend CRUD routes for managing design analyses. These routes handle saving analysis results (with thumbnail), listing, retrieving, and deleting analyses. All routes require authentication and use RLS through the user-scoped Supabase client.

## Tasks

<task name="create-analyses-routes">
Create `api/src/routes/analyses.ts`:

Routes (protected by auth middleware):

### `POST /api/analyses` — Save a new analysis
Request body:
```json
{
  "name": "Design name (from filename or user input)",
  "thumbnail": "base64 data URL of the analyzed image (resized to ~200px for list display)",
  "resultJson": { /* full DNA analysis JSON */ }
}
```
- Inserts into `analyses` table with `user_id` from auth context
- Returns `{ id, name, created_at }`

### `GET /api/analyses` — List user's analyses
- Queries `analyses` table filtered by user (RLS handles this)
- Ordered by `created_at DESC`
- Returns array of `{ id, name, thumbnail, created_at }` (NO result_json — too large for list)
- Optional `?limit=20&offset=0` for pagination

### `GET /api/analyses/:id` — Get single analysis
- Returns full `{ id, name, thumbnail, result_json, created_at }`
- 404 if not found (RLS ensures user can't access others')

### `DELETE /api/analyses/:id` — Delete analysis
- Deletes from `analyses` table
- Returns `{ success: true }`
- 404 if not found

All error responses: `{ code: string, message: string }` (consistent with Phase 10 pattern)
</task>

<task name="register-routes">
Update `api/src/index.ts`:

```typescript
import { analysesRoute } from './routes/analyses.js';
app.route('/api', analysesRoute);
```
</task>
