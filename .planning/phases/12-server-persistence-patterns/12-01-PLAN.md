# Plan 12-01: Backend Patterns CRUD Routes

## Objective
Create backend CRUD routes for managing saved pattern libraries (from Compare analyses). These routes handle saving pattern results, listing patterns, retrieving a specific pattern, and deleting patterns. All routes require authentication and use RLS.

## Tasks

<task name="create-patterns-routes">
Create `api/src/routes/patterns.ts`:

Routes (protected by `authMiddleware`):

### `POST /api/patterns` — Save a new pattern
Request body matches the DB schema:
```json
{
  "name": "Pattern Name",
  "summary": "Extracted from winning formula",
  "sourceImageCount": 5,
  "thumbnails": ["data:image/jpeg;base64,..."],
  "batchAnalysis": { /* full batch_analysis JSON */ }
}
```
- Inserts into `patterns` table with `user_id` from auth context.
- Returns `{ id, name, created_at }`

### `GET /api/patterns` — List user's patterns
- Queries `patterns` table filtered by user (via RLS).
- Ordered by `created_at DESC`.
- Returns array of `{ id, name, summary, source_image_count, thumbnails, created_at }`
- **Crucial:** DO NOT return `batch_analysis` for the list endpoint (query only specific columns) as it's too large for a list view.

### `GET /api/patterns/:id` — Get single pattern
- Returns full pattern object including `batch_analysis`.
- 404 if not found or unauthorized (RLS).

### `DELETE /api/patterns/:id` — Delete pattern
- Deletes from `patterns` table.
- Returns `{ success: true }`.
- 404 if not found.

All endpoints must return errors in standard format: `{ code: 'err_code', message: '...' }`.
</task>

<task name="register-patterns-route">
Update `api/src/index.ts`:

```typescript
import { patternsRoute } from './routes/patterns.js';
app.route('/api', patternsRoute);
```
</task>
