**PROMPT 1: APP SCAFFOLD (Mock Data)**

This is the main scaffold prompt. It must instruct Gemini to build:

1. **App Shell:**
   - Topbar: 56px height, surface1 bg, "DesignDNA" logo left (text + small gradient icon)
   - Simple state-based routing: `currentScreen` state → landing | upload | analyzing | results
   - No react-router — conditional rendering

2. **Landing Screen:**
   - Hero: H1 "Decode Any Design's DNA" + subtitle explaining Visual + Buyer DNA analysis
   - 3 Action Cards (grid, 3 columns desktop):
     - "Analyze Design" — upload icon, primary action → navigates to upload
     - "Compare Designs" — compare icon, "Coming soon" badge, disabled
     - "Generate Design" — magic icon, "Coming soon" badge, disabled
   - Each card: surface1 bg, border, radius 12px, hover state

3. **Upload Screen:**
   - Centered layout, max-width 640px
   - Upload zone: dashed border, drag & drop + click to browse, accepts images (PNG/JPG/WEBP)
   - FileReader → preview image after upload
   - After upload shows:
     - Full image preview (max-height 400px, object-fit contain, rounded)
     - Mode selector: 2 radio-style cards side by side
       - "Quick Scan" — "Visual DNA only · ~10 seconds" — default selected
       - "Deep Analysis" — "Visual + Buyer DNA · ~30 seconds"
     - "Analyze Design" button (AI gradient, full width)
     - "Change Image" ghost button below
   - Back button to landing

4. **DNA Card (Results Screen):**
   - Split layout: 40% image left (sticky), 60% content right (scroll)
   - Image panel: uploaded image, rounded left corners
   - Tab bar: "Visual DNA" | "Buyer DNA" tabs (underline style)
   - **Visual DNA tab:**
     - Brief summary paragraph at top (2-3 sentences synthesizing the analysis)
     - 5 sections stacked: Composition, Color, Typography, Graphics, POD Technical
     - Each section: H3 title, fields as `Label: Value` inline pairs
     - Color section: proportional color bar (5 segments) + hex codes below + harmony/contrast/temperature
     - Typography: font classifications + suggested Google Fonts visible
   - **Buyer DNA tab:**
     - Sections in order: **Made For Me** (first!) → Persona → Identity Signals → Emotional Triggers → Occasion & Timing
     - Made For Me: each decision as a mini-card (surface2 bg, 8px radius) with bold decision title + conversational explanation below
     - Persona: inline Label:Value pairs (age, gender lean, interests as tags, values as tags, lifestyle as paragraph, spending mindset, communities as tags)
     - Other sections: similar inline layout
   - "Analyze Another" button (secondary) → back to upload
   - "Generate from DNA" button (AI gradient, disabled, "Coming Soon" tooltip)
   - "Compare Designs" button (secondary, disabled, "Coming Soon" tooltip)
   - Mobile: stack vertically, image full-width top

5. **Loading State (Analyzing Screen):**
   - Show while "analyzing" — skeleton matching DNA Card layout
   - Shimmer animation on skeleton blocks
   - Text: "Analyzing your design..." with mode label ("Quick Scan" or "Deep Analysis")
   - After "analysis complete" (simulated 2s delay with mock data), DNA Card fades in with staggered reveal (100ms between sections)

6. **Mock Data:**
   Use the outdoor hiking design example from APP-CONCEPT-V2 Section 4 as hardcoded mock data. Include the full Visual DNA + Buyer DNA JSON. This data renders in the DNA Card immediately after the simulated loading.

7. **General Rules in Prompt:**
   - Follow System Instructions design system exactly (already pasted)
   - All screen transitions: fade + translateY(8px), 200ms ease-out
   - Components use design tokens from System Instructions — do NOT hardcode colors
   - Responsive: desktop split, tablet stacked, mobile single-column
   - No external packages — everything self-contained

**KEY PROMPT WRITING RULES:**
- Reference System Instructions ("follow the design system in your System Instructions") — do NOT repeat tokens
- Be specific about layout (px values, flex/grid, gaps) but concise
- Use instruction-first format (research finding: instruction-first > narrative)
- Do NOT include JSON schema in prompt — it's in System Instructions already
- Include the mock data JSON inline in the prompt for Gemini to use

**PROMPT 2: WIRE LIVE GEMINI API**

Follow-up prompt that replaces mock data with real API calls:

1. Replace simulated delay with actual Gemini API call:
   - Quick Scan: call gemini-2.5-flash with image + Quick Scan prompt template
   - Deep Analysis: call gemini-2.5-pro with image + Deep Analysis prompt template
   - Use `fetch` to Gemini API endpoint with API key from environment/config
   - Parse response JSON → populate DNA Card

2. Add proper loading states:
   - Skeleton layout matching DNA Card structure
   - "Analyzing..." text with elapsed time counter
   - Cancel button to abort

3. Add error handling:
   - Network error → "Failed to connect. Check your internet and try again." + Retry button
   - API error (rate limit, invalid image) → specific error message + suggestions
   - Timeout (>60s) → "Analysis is taking longer than expected." + option to retry or try Quick Scan
   - Invalid response format → "Unexpected response. Please try again." + Retry

4. API key configuration:
   - Input field in a Settings modal (gear icon in topbar)
   - Store in localStorage
   - Validate key format before saving
