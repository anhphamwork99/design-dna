# Plan 10-04: Settings UI — Server-Side API Key Management

## Objective
Update the Settings modal to manage API keys stored server-side (encrypted in Supabase) instead of localStorage. User can save, update, and delete their Gemini API key through the backend.

## Tasks

<task name="create-settings-component">
Extract `SettingsModal` from `App.tsx` into `app/src/components/SettingsModal.tsx`:

Updated behavior:
1. **On open:** Call `GET /api/api-keys` to check if user has a saved key → show "Key saved ✓" or empty input
2. **Save key:** Call `POST /api/api-keys` with `{ key: inputValue }` → key encrypted server-side
3. **Delete key:** Call `DELETE /api/api-keys` → removes key from Supabase
4. **NEVER display** the actual key value (server never returns it)

UI states:
- **No key saved:** Show input field + "Save" button
- **Key saved:** Show "Your API key is saved securely ✓" + "Update" and "Delete" buttons
- **Updating:** Show input field pre-filled with "••••••••" placeholder + "Save" button
- **Loading:** Show spinner while checking key status
- **Error:** Show error message from backend

Use `useAuth()` hook to get session token for API calls.

Copy/info text: "Your key is encrypted and stored securely on our server. It's never exposed to the browser."
</task>

<task name="update-app-settings-integration">
Update `App.tsx`:

1. Import `SettingsModal` from `./components/SettingsModal`
2. Remove old inline `SettingsModal` function
3. Remove `apiKey` state and localStorage logic for API key
4. Settings modal no longer auto-opens on missing key — user sees it on first API call failure (backend returns `NO_API_KEY` error code)
5. Handle `NO_API_KEY` error in API call catch blocks → auto-open Settings modal
</task>

<task name="remove-localstorage-key">
Clean up all references to `localStorage.getItem('designdna_api_key')`:

- `App.tsx` — remove from `handleAnalyze`, `handleCompareAnalyze` 
- `CreativeStudio.tsx` — if any references remain

After this, the only localStorage usage should be for patterns (Phase 12-13 will handle that).
</task>
