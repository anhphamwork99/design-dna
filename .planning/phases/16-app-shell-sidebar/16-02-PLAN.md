  **3. Refactor `app/src/App.tsx`:**

  This is the biggest change. The goal is:
  - Auth gate stays at top (loading, unauthenticated → Login/Register)
  - Authenticated → `<AppShell>` wrapping `<Routes>`
  - Remove the old `<header>` completely (sidebar replaces it)
  - Remove `LandingScreen` function (lines ~469-522)
  - Remove `currentScreen` / `setCurrentScreen` state
  - Keep ALL existing screen components (UploadScreen, AnalyzingScreen, ResultsScreen, etc.) as inline functions for now — they will be extracted in Phase 17

  **Route mapping:**

  | Route | Component | Notes |
  |-------|-----------|-------|
  | `/` | `<HomeScreen />` | New placeholder |
  | `/analyze` | Analyze flow wrapper | Upload → Analyzing → Results flow. Use a wrapper component or nested state. Keep existing `handleAnalyze` logic. |
  | `/studio` | `<CreativeStudio />` | Existing component |
  | `/compare` | Compare flow wrapper | Upload → Analyzing → Results. Keep existing `handleCompareAnalyze`. |
  | `/library` | Library wrapper | Show tabs/sections for both PatternLibrary and MyAnalysesList. For Phase 16, simply render `<PatternLibrary />` as placeholder. |
  | `/library/pattern/:id` | `<PatternDetail />` | Pattern detail route |
  | `/library/analysis/:id` | `<ViewAnalysisScreen />` | View saved analysis |
  | `/settings` | Open SettingsModal | For Phase 16, keep Settings as modal triggered from sidebar. Route can just open the modal. |

  **Important implementation details:**
  - The Analyze and Compare screens have multi-step flows (upload → analyzing → results). Keep this as internal state within wrapper components or keep the existing state management within App.tsx for now. The key requirement is that clicking "Analyze" in sidebar always starts from the upload step.
  - Import `Routes, Route` from `react-router-dom`
  - Import `AppShell` from `./components/layout`
  - Import `HomeScreen` from `./screens/HomeScreen`
  - Keep the migration banner somewhere — either inside AppShell or remove temporarily (it's rarely triggered)
  - Settings sidebar item: Can use `onClick` to toggle modal (doesn't need a real route in Phase 16)
  - Sign out sidebar item: Uses `signOut` from AuthContext
  - Each route component should set `document.title` via useEffect for accessibility

  **Screens that DON'T have sidebar routes but need internal navigation:**
  - UploadScreen, AnalyzingScreen, ResultsScreen → all part of `/analyze` flow
  - CompareUploadScreen, CompareAnalyzingScreen, CompareResultsScreen → all part of `/compare` flow

  **Minimal refactor approach (recommended):**
  Keep the `currentScreen` state for sub-flows within Analyze and Compare routes. Only the TOP-LEVEL navigation switches to Router routes. Sub-steps within each tool stay as state-driven.

  ```tsx
  // Example structure
  <AppShell>
    <Routes>
      <Route path="/" element={<HomeScreen />} />
      <Route path="/analyze" element={<AnalyzeFlow />} />
      <Route path="/studio" element={<CreativeStudio ... />} />
      <Route path="/compare" element={<CompareFlow />} />
      <Route path="/library" element={<LibraryScreen />} />
      <Route path="/library/pattern/:id" element={<PatternDetail ... />} />
      <Route path="/library/analysis/:id" element={<ViewAnalysisScreen ... />} />
    </Routes>
  </AppShell>
  ```

  Where `AnalyzeFlow` and `CompareFlow` are local components that manage their own multi-step state internally (using the existing code from App.tsx).
